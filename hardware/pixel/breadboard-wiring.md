# 面包板布线约定（pixel）

> 物理约束见库仓 `AGENTS.md` **§5b**（一孔一线 / 颜色含义 / 允许 45° 折线不许盖元件 ✓）。
> 本文只写**本项目**的约定 ✓。

## 0. ★ 面包板要的是**物理连接**，不是"同名即通"（2026-09-26 用户定 ✓）

- **netlabel / 网名是抽象连接** ✗ ⇒ **只适用于原理图** ✓（同名即同网 ✓ 是画原理图的简称手法 ✓）；
  **面包板上没有任何"抽象"** —— 两根线之间**必须**有导体（导线 ✓ 或同一条 bus 的铜片 ✓），
  否则就是没连 ✓。
- 推论（写生成器/写自检时必须遵守 ✓）：
  1. **不许**把"元件脚属于同一个网"当成"它们已经连上了" ✗ —— 同网只是**待办清单** ✓
     （告诉我"这几个脚最终要连成一片"✓），**不是**现成的连接 ✓；
  2. **一条 bus 上挂了两个不同网的脚 = 实物短接** ✗（那一列 5 个孔是**同一块铜片** ✓）
     ⇒ 这是**布局错误** ✓，必须挪脚 ✓；**不许**把它当"两网已合并"去补线 ✗。
     反例教训（本日 ✓）：`bus21` 上 `C1` 的 GND 脚(`21F`) 与 `R1` 的 RC 脚(`21G`) 同列 ⇒
     我把它当成"GND+RC 一片"去布线 ⇒ **RC 自己一根线都没有** ✗、还多出 `21H→22H`、
     `36H→38H` 两根"跨过 C1"的假线 ✗，而自检却报「10 网连通 ✓」✗✗；
  3. **自检要能区分"接通"与"被短接"** ✓：先查"没有 bus 跨两个网" ✓，再查连通 ✓
     —— 顺序反了就会像我一样报假通过 ✗。
- 机器守：`bb_route4.py` 先跑**布局短接硬闸门** ✓（有就报错 + **不写文件** ✗）。

## 0b. ★ 两条引线规则（2026-09-26 用户定 ✓）

- **① 引线不遮挡「接线了的孔」** ✗（用户原话 ✓）—— 孔上有东西（元件脚 ✓ 或跳线端点 ✓）时，
  引线不能把它的开口盖住 ✓；**我的取值：盖住开口面积 > 30% 就算遮挡** ✗（可调 ✓）。
  为什么取 30%（实测 ✓）：孔的开口半径 **1.496 单位**（板子 svg `r=1.197` 局部 ⇒ 直径 **0.845mm** ✓），
  跳线带宽 **2.00 单位**（22.2222 mil = 0.564mm ✓）⇒ 盖 30% ≈ 导线中心离孔心 **≥0.34mm** ✓；
  >50% ≈ 0.24mm（偏松 ✗）、>80% ≈ 只有正中心才算（太松 ✗）。
  机器守：生成器把它当**硬规矩** ✓（“严格路”直接否决 ✓；只有回退时才允许并重罚 ✓），
  自检直接报「遮挡接线孔 N 个 ⇒ 必须 0」✓。
- **② 引线尽量分散均匀、不过度拥挤** ✓（用户举例：某根该走右侧空地，却去挤中间 ✗）。
  做法：候选路算分时，每条段统计**附近（<6 单位 ≈ 1.7mm）有几根已有的线** ✓，
  按 `×(1 + 0.30×邻居数)` 罚 ✓ ⇒ 空地优先 ✓；自检报「拥挤度（每段平均近邻数）」✓ 做基线。
- **③ 一个脚只能「插孔」或「接一根引线」——二选一** ✓（2026-09-26 用户看图指出 ✓）：
  引线**不许**落在已插孔的脚上 ✗（要接**同一条 bus 里的空闲孔** ✓）；
  只有**没插孔**的焊盘（如 U1 的 EPAD 焊盘 ✓）才可以直接接线 ✓。
  例：EPAD 焊盘 → **GND 电源轨**（`pin31Z` ✓ —— 2026-09-26 用户定 ✓：
  「数据手册常说 EPAD 接 VSS，**只适用于 PCB**；面包板 / 原理图 / PCB 有各自的逻辑和美学」✓
  ⇒ 面包板上要看得见"特意接到地" ✓，接到本元件自己的 GND 脚所在的 bus 画出来像"芯片内部连着" ✗
  ⇒ **废** ✗；同理原理图上它接 **LED2 的 GND 脚** ✓，也不是 U1 自己的 pin4 ✗）。
  ★ “正下方那个孔”常常用不了 ✓：实测 `pin36G` 正好被 **U1 的板体遮住** ✗（被遮孔不能用 ✓），
  反正现在也不再用那一列了 ✓。
  机器守：回读自检报「wires on plugged pins N ⇒ 必须 0」✓。
- **④ 不许为了折线而绕远路** ✗（同日用户看到「绕了个大圈子」✓）：打分**以长度为主** ✓，
  折线不给加分 ✗ —— 折线只在能躲开元件/别的线/孔时出现 ✓。
- **⑤ ★ 引线尽可能少相交** ✓（2026-09-26 用户定 ✓，**优先于**④里的“长度为主”✓）：
  交叉的地方一看就乱、查线也容易看错 ✓ ⇒ **交叉数是头号指标** ✓（排在总长/段数前面 ✓）。
  做法（两道 ✓）：① 路的分里给交叉加权 ✓（贪婪阶段）；② 收尾跑**抽出重排** ✓
  —— 把一根抽出来、在**能看见其它所有线**的条件下重算它 ✓，只在指标变好时才采纳 ✓
  （贪婪布线看不见后面放的线 ✗，实测会多出交叉 ✗）。
  量两版差异 / 量任何一版：`py -3.13 bb_compare.py <A.fzz> [<B.fzz>]` ✓
  （手改草稿 `*_byHand.fzz` 已 gitignore ✓，但它可以直接拿来当 B 量 ✓）。
- **⑥ ★★ 美学原则：少相交 = 简单 = 美** ✓（2026-09-26 用户定 ✓，原话：
  「通过修改跳线位置和走向，让图的交叉点减少，从而看起来简单，人看着它觉得简单 =
  人看着它觉得舒服 = 美」✓）。用户给的两个实例（同日 ✓）：
  · 两根作用相同的黑线：右那根跟**元件、跳线有多个交集** ⇒ 不美 ✗；
    左那根**只与一根线相交** ⇒ 美 ✓；
  · 两根红线：斜的那根**与黑线相交两次** ⇒ 不美 ✗；折的那根**跟任何元件都没交集** ⇒ 美 ✓。
  ⇒ 三条判据：
  1. 判据是**交叉数** ✓ —— 同一根线被交叉两次 = **2** 次 ✓（不是“一次” ✗）；
  2. “交集”包括**与元件**相交 ✗（不只线↔线 ✓）；
  3. 降交叉的手段：换接孔 ✓ / 改走向 ✓（正交折线 ✓）——**正交（横平竖直 / 折线）
     比斜线好看** ✓（实测：用户点名“不美”的两根都是斜线 ✗，点名“美”的都是正交或折线 ✓）；
     但**折线不给加分** ✗（第 9 条：不许为了折线而绕远路 ✓）。
- **⑦ ★★ “交集”的准确定义 = 三条一起算**（2026-09-26 当天修正 ✓）：
  **交集 = X 形交叉 + T 形搭线（一方端点搭在对方段内 ✗）+ 从元件本体底下穿过** ——
  三类都算 1 次 ✓；**同一根线被交叉两次 = 2 次** ✓；
  两根线接**同一个孔**、或同一根线的两段在端点相接 ✓ **不算** ✗。
  ★ 我先后只数了 X ✗ ⇒ 目标函数与用户看到的不是一个东西 ✗ ⇒ 越优化越不像“人看着舒服” ✗；
  修正后同一张图 9 → 3 ✓（用户手改版 byHand = 4 ✓ ⇒ 生成版第一次**优于手改版** ✓）。
- **⑧ ★★ 判碰只有“一份实现”** ✓：`bb_compare.pair_kind(a,b,c,d)` ✓ ——
  **度量（看图的工具 ✓）与优化器（布线器 ✓）都调它**，不许各写一套 ✗。
  以前两套实现 + 两套包围盒混用 ✗ ⇒ 数字对不上、找不到原因 ✗（当天踩过 ✗）。
- **⑨ ★★ 不许“自证”** ✗（当天最大教训 ✓）：布线器的自检与布线器**共用**同一个
  几何定义/包围盒 ✗ ⇒ 它有错时两边一起错 ✓，自检永远通过 ✗。
  ⇒ 硬要求：**结论必须能被“另一个实现”或“人的眼睛”推翻** ✓ ——
  ① 数量结论用 `bb_compare.py`（独立于生成器 ✓）复核 ✓；
  ② 与用户手改版对量 ✓；③ 最终以**渲染/用户截图**为准 ✓。
  另外：自己新写的 svg 解析器（把 `path/@d` 的数字当点 ✗）曾把盒子算大 ✗ ⇒
  **新写一套几何读取前，先与已验证的老实现逐件对一遍** ✓（对不上就不能混用 ✗）。
- **⑩ ★ “改一处”要同时看“比的对象”是否同一条件**（当天第三个 bug ✓）：
  重排一根 EPAD 线时，**旧路由**忘了传“自己的元件豁免”✗、**候选路由**传了 ✓ ⇒
  每次比较都是 1→0 ✗、永远“有改进” ✓ ⇒ 同一根线被反复“重排”、全局一动不动 ✗
  （实测连着 8 轮重复 ✗）。教训：**比较的两边必须用同一组参数**✓。
- **⑪ ★★ 目标函数：代价 = 长度 + K × 交集** ✓（2026-09-26 用户定 ✓）
  ★ **K = 10 mm / 个交集** ✓ —— 这是**人为选定的经验值** ✓，**是一个可以随时调整的系数** ✓
  （不是从数据里推出来的物理量 ✗）。含义：为了少 1 个交叉，最多值得多绕 K 毫米 ✓；
  超过就不划算 ✗。调大 = 更看重“少交叉” ✓；调小 = 更看重“短而直” ✓；
  代码里就一行：`bb_route4.py` 的 `K_MM = 10.0` ✓（每次运行都在日志里打印 K ✓）。
  为什么需要它：以前是“交集优先、长度只当平手判据” ✗ ⇒ 为了省 1 个交叉肯绕 4 倍长度 ✗
  （实测 EPAD 被绕到 94mm ✗）。K 是**手感旋钮** ✓，最终以人看着舒服为准 ✓。
  ★ 两段式：前几轮**只按“少交叉”排** ✓、后几轮**按加权代价算账** ✓ ——
  若全程用加权 ⇒ 它会为了减长度到处加交叉 ✗（实测直接掉到 6∼9 个 ✗）。
- **⑫ ★★ 遮挡面积公式曾经写错（2026-09-26 用户追问后查出 ✓，最大的一个 ✗）**：
  `obscures()` 里算“导线带盖住孔的面积比”的圆弓公式，**平方根项符号写反了** ✗
  ⇒ 覆盖率只算真值的 **~1/5** ✗（实测：一根线正好穿过孔心，真值 **78%** ✓、旧公式报 **15%** ✗）。
  ⇒ “孔被别的引线盖住 >30% 就算违规 ✗”这条硬规则一直**形同虚设** ✗；
  布线器对遮挡的惩罚、`covered_by_wires()` 的拦截也一起失效 ✗。
  ⇒ 修完用独立脚本 `_scratch/audit_holes.py` 复核三版：
  v19 **1 处**（`pin34H` 被盖 78% ✗）、v8 **2 处**、v12 **0 处** ✓ ——
  可见之前那几版“看起来更优”有一部分是**几何闸门失效**换来的 ✗。
  ★ 教训：公式也必须有**数值真值校验** ✓（穿心 = $2(h\sqrt{R^2-h^2}+R^2\arcsin\frac{h}{R})/(\pi R^2)$ ✓），
  不能只看“代码能跑” ✗；且同一个公式**只能有一份实现** ✓（布线器里那份抄错了 ✗，现已改为直调
  `bb_compare.obscures` ✓）。
- **⑬ ★★ 留路：先布的“电源/地”走轨与板边，中间走廊留给信号线** ✓（2026-09-26 用户定 ✓，规则 a ✓）
  起因（实测 ✗）：按次序“先布电源/地”后，GND 把 `BR+` 唯一的那条中间走廊（row H，y=63 ✓）占掉了 ✗
  ⇒ 后布的信号线无处可走 ✗（`net BR+: 连不上` ✓）。
  ⇒ 规则：**留路不只是给元件、也是给后面的线** ✓ ——
  GND/5V（组 0/1 ✓）的代价里给“走中间”的那段加权 ✓（能走电源轨/板边就走 ✓）；
  信号线（组 2 ✓）不受此限 ✓（中间本来就是它们的地盘 ✓）。
- **⑭ ★★ 元件在面包板上的摆位（2026-09-26 用户定 ✓）**：
  · **单排针**的元件 ⇒ 可排在上半区（F..J ✓）**或**下半区（A..E ✓）；
  · **两排针**的元件 ⇒ **必须骑中缝** ✓：一排在上半区、另一排在下半区 ✓
    ⇒ **y 方向没有自由度** ✗（只能是“骑缝”那一档 ✓）。
  ★ 推论（实测 ✓）：两排针模块的 5 孔 bus 是**朝上**伸的 ✓
  （例如 U1 的焊盘在 F/E ✓，它的可用孔在 F..J 那一列 ✓）⇒ 摆到下半区时 bus 会伸进自己的板里 ✗
  ⇒ 布线器一开场就报“bus 没有空孔” ✗。
  ⇒ 做法：**先放 y 锁死的两排针模块**（又宽又没得选 ✓）、单排针再**填缝** ✓；
  骑电源轨的元件（去耦电容 ✓）必须落在**真轨孔列**上 ✓（轨孔是“4 个一组、隔一列空” ✓、列 3..61 ✓）。
- **⑮ ★★ 元件布置的四条硬约束（2026-09-26 实测 ✓）**：
  1. **孔必须真实存在** ✓ —— 电源轨只有 **50 列孔** ✗，不能按“10×63”算
     （否则算出 `pin2W` ✗ ⇒ 布线器 KeyError ✗）；
     判据源头：**板零件自己的 connector 集合** ✓（`hole_set` ✓）。
  2. **本体板不许越出板边** ✗（板边 = 孔阵外扩半个孔距 ✓）—— L1 曾被摆到 y=−40 ✗。
  3. **每条被用到的 bus 都要剩空孔** ✓，且必须**对称校验** ✓：不只看新放的零件 ✓，
     还要看**先前已放好零件**的全部脚 ✓ —— 新放的板子同样能把它们的 bus 盖满 ✗
     （实测：J2 的 D 行 bus 被后来的板子盖满 ✗ ⇒ 布线器开场报 `bus 没有空孔` ✗）。
  4. ★★ **“盖住”判定必须带容差** ✗（2026-09-26 根因 ✓）：本体板框是**过实例 transform**
     算出来的 ✓，带 1e-4 级浮点误差 ✗ ⇒ 用**精确边界**比会把**正好压在板边上**的那排孔
     判成“没盖住” ✗（实测：J2 板底边 `108.00009` vs 孔 `y=108.0` ✗ ⇒ 四条 bus 全判漏 ✗，
     而人看是“完全盖住” ✗）。⇒ 统一用 **`COVER_EPS = 1` 单位**（= 0.28mm ✓），
     与布线器（`bb0_route4` 的 `bx0-1 <= hx` ✓）**同一个口径** ✓。
  ★ 另有两条派生结论：**(a) “允许的 y 偏移”要算出来** ✓（由上面 4 条推 ✓），不能写死清单 ✗
  （写死 `(0, ±27)` ✗ ⇒ 20mm 高的 L1 报“放不下” ✗，它真正的合法偏移是 **+18** ✗ 不在清单里 ✗）；
  **(b) 放不下的根因要能点名** ✓（布线器报 `bus 没有空孔` 时**指名**是哪条 bus、上面插着谁、
  被哪块板子盖住 ✗ —— 不点名就只能靠猜 ✗）。
- **⑯ ★★ 电源/地怎么布才算对（2026-09-26 实测 ✓）**：
  · **对侧那条电源轨也算本网资源** ✓（GND ↔ Z/X ✓、5V ↔ Y/W ✓，同一网才可以 ✓，交叉就是短路 ✗）：
    ★ 动机（实测 ✗）：地网的锚点只有一条轨（EPAD 接上去那条 ✓ = **Z** ✓），
    而**骑中缝的模块**（D3：板盖住 G..D 行 ✓）**下半区的脚**只能从下方出线 ✗
    ⇒ 被迫翻过自己的板子去够上轨 ✗ ⇒ 实测绕出 **147mm** ✗ 而且最后還连不上 ✗。
    把 X 的一个空孔加进地网后，**两条轨之间的干线由布线器自己拉** ✓（实测 `pin59Z→pin59X`
    **45.7mm** ✓，落在板边 ✓ = 规则 a ✓）。
  · **电源/地按“星形”接轨** ✓（每条非轨 bus 就近接一条轨 ✓），**不要**让它们自由配对 ✗：
    实测自由配对会把 D3 的 E-bus 直接连到很远的 J2 bus ✗（**147.3mm** ✗），
    而那根线又横着压住了 D3 自己 bus 的孔 ✗ ⇒ 最后 `pin3E` 连不上 ✗。
    改成星形后实测：GND = `8.0 / 8.0 / 10.2 / 7.6 / 25.4 / 10.5 / 10.2 / 40.6 mm` ✓、
    5V = `8.0 / 8.0 / 27.9 / 8.0 / 23.4 mm` ✓ —— **全都是“轨→脚”的短竖线** ✓（跟用户手画那两根一个风格 ✓）。
- **⑰ ★★ 「留路」要按 bus 判、不要按孔判（2026-09-26 实测 ✓）**：
  · 规则 ⑩ 的正确形式：**一条 bus 里 5 个孔 ✓，只要还能剩一个可用孔 ✓**，
    后面那个网就仍能用它 ✓ ⇒ 才允许压 ✓。按“碰到哪个孔就不行”❌ 会把
    **整条 J 行走廊**全禁掉 ❌ ⇒ 实测 `DATA_OUT`（U1 的脚 → J1 的脚）就是这样被
    卡死的 ❌（1809 个候选全废 ✗）。
  · 另外补了两种**走法形状**（实测缺的 ✓）：
    ① **绕“墙”的三折**：把中间那条线放在**两个元件框之间的空当**（框外 ±1.5 孔距 ✓）
      —— 实测 `COIL_A` 需要它 ✓（L1 的脚只能从 F 行出 ✓、D3 的脚只能从 J 行出 ✓，
      而 F 行横着别人要用的孔 ✓）；
    ② **绕一个框的“U 形”（4 个弯）**：`当 `J1` 这种上半区的墙 ✓，需要“从框左边下去 +
      从框右边上来”✗（三折表达不了 ✓）。
- **⑲ ★★ 删旧导线时，必须同时删“孔 → 那根线”的记录** ✗（2026-09-26 用户截图实测 ✓）：
  · 症状（用户看到的 ✓）：在 Fritzing 里**悬停一个孔 ⇒ 一大片孔都亮** ✗ ——
    看起来像“很多孔被错误地连在一起” ✗。用户原话：「似乎有错误的网，导致很多点是通的」✓。
  · 根因：布线器删了旧 `Wire` 实例 ✓，但**板子连接表**里 “孔 → 那根线” 的
    `<connect modelIndex=…>` 还留着 ✗ ⇒ 指向**不存在的实例** ✗ ⇒ Fritzing 就把它当成
    “接在一根看不见的线上” ✗。

## 2b. ★ 电源轨的**行约定**：第一行 = GND(蓝) / 第二行 = 5V(红)（2026-09-26 用户定 ✓）

- **红线 = 正极、蓝线 = 负极** ✓ —— 这是面包板的通行读法 ✓，而**板子自己的 svg 就是这么印的** ✓：
  实测（`breadboard2.svg` ✓）上行组 **第一行 Z 上方** 那条线是 `#0000FF`（蓝 ✓）、
  **第二行 Y 下方** 是 `#FF0000`（红 ✓）；下行组同理（X 上方蓝 ✓、W 下方红 ✓）⇒
  **第一行(Z/X) = 负极 = GND ✓、第二行(Y/W) = 正极 = 5V ✓**（用户原话：「5V 应该接第二行，
  GND 接第一行」✓）。
- 机器守：`fix_breadboard_layout.py` 里已把 `C2` 两只脚对调到「5V→`30Y` ✓ / GND→`29Z` ✓」✓；
  以后**凡是能落在轨上的电源脚，都按这条落** ✓（落在轨上 = 同一条长 bus ⇒ **一根线都不用** ✓）。
- 例（本板 ✓）：`5V` 的轨脚 = `pin30Y`（第二行 ✓）、`GND` 的轨脚 = `pin29Z`（第一行 ✓）。

## 4. 跳线规则（生成器要满足 ✓）

1. **一孔一线** ✓：`元件脚已插的孔`一律**不接跳线** ✗ ⇒ 跳线接在**同一条 bus 内的空闲孔** ✓，
   且**每个空闲孔最多用一次** ✓（生成时报「占用孔冲突数」✓，必须 **0** ✓）；
2. **5V / GND 走电源轨** ✓（用户 2026-09-26 定 ✓）；轨上取孔也遵守第 1 条 ✓；

4. 生成后自检：① 每孔占用 ≤1 ✓ ② 含 bus 的**脚级**连通性 = 10 网全通 ✓ ③ 线端落在孔心（标定残差 ✓）。
