# 面包板布线器：复盘与重做方案（2026-09-26）

起因：把「孔被别的引线盖住 >30%」的**遮挡面积公式**修正后（`obscures()` 原来平方根项符号写反 ✗，
覆盖率只算真值的 ~1/5 ✗），布线器**跑不出合法结果了** ✗ ——
`net GND: no clean route left -> overlapping direct link` ✗、
收尾 `overlap 1` ✗ + `connected holes hidden 2` ✗ ⇒ 自检拒绝写文件 ✓。

也就是说：**之前那些"看起来更优"的版本，有一部分是靠几何闸门失灵换来的** ✗。
这不是一个可以继续打补丁的小问题 ✗ ⇒ 按下面的顺序从头梳理 ✓。

---

## 0. ★★ 布线次序（2026-09-26 用户定 ✓，**最高优先级** ✓）

从大到小、从主到次：

1. **元件布置**：用户没指定位置时 ⇒ 按原理图**从左到右**布置元件 ✓；
   主要元件周围要**留出走线空间** ✓。（当前工程位置是用户在 Fritzing 里摆好的 ✓ ⇒ 本轮不自动布置 ✗）
2. 元件定位后，**从左到右、从上到下**，依次布**电源线和地线** ✓。
3. 再**从左到右、从上到下**布**其它线** ✓。
4. **布线原则：长度代价 + 拥挤代价** ✓（再加上人定的汇率：$K\times$交集 ✓）。
5. **核心算法**：一孔对一针或一线 ✓（互斥 ✓）、遮挡数算法 ✓、汇率换算 ✓。
6. ★★ **先布的电源/地 走“电源轨与板边”、把中间走廊留给信号线** ✓
   （2026-09-26 用户定 ✓ —— 接住“先布电源/地”带来的副作用：实测先布的 GND 会把
   BR+ 唯一的那条中间走廊吃掉 ✗ ⇒ 后布的信号线无路可走 ✗）
   ⇒ 含义：**留路不只是给元件，也是给后面的线** ✓（第 1 条的延伸 ✓）；
   实现：GND/5V（组 0/1 ✓）的代价里给“走中间”的那段加权 ✓（能走轨/边就走轨/边 ✓），
   信号线（组 2 ✓）不受此限 ✓。

⇒ 布线器的现状**不符合第 2/3 条** ✗（它按网表顺序放线 ✗）—— 下一步就改这里 ✓。

## 2. 核心短板（直说）

1. **没有模型，只有"逐个放置 + 手调权重"** ✗
   现在是一根一根放线 ✓，每根按一个**乘法堆出来的代价**挑 ✓（7 个乘子 + 若干 magic number ✗）。
   ⇒ 结果**依赖放置顺序** ✗、动不动卡在局部最优 ✗（实测卡在 6 ✗），
   而且**换个目标函数就得重跑全流程、旧结论全部作废** ✗。
2. **硬约束散落在惩罚项里** ✗
   "不许盖住接线孔 ✓ / 不许压别的元件 ✓ / 一个孔只能一个端点 ✓ …" 既有硬判废 ✓、
   又有软惩罚 ✗ ⇒ 修一处忘一处 ✗（这次就是公式错 + 三处调用同时失效 ✗）。
3. **验证长期是"自证"** ✗
   量交集的、算遮挡的、判合法性的，全都调**同一份**几何代码 ✗ ⇒ 它错时两边一起错 ✓、
   自检永远通过 ✓（一个符号错误活了很久 ✗）。独立的 `bb_compare.py` 只覆盖了"交集"这一项 ✗。
4. **我把"能跑通"当成了"验证过"** ✗
   每次都报告"自检 ✓ / 独立工具 ✓"，但**没有主动说**"几何闸门本身没被验证过" ✗。
   结果上等同于藏了一个大问题 ✗ —— 不是故意隐瞒 ✓，但性质一样 ✗，改法只有一个：
   **每一条硬约束都要有独立的、能从文件出发复核的实现** ✓（并且每条都要有数值真值自测 ✓）。

## 2b. 诊断（2026-09-26，v21 之后 ✓）

把遮挡公式改对、再把布线次序按用户规则改好之后，还是 **跑不出合法布局** ✗（1 处重叠 + 2 处遮挡 ✗）。
诊断结论：

- **候选太薄** ✗ —— 只试“最近的 12∼30 对孔” ✗ + 少量折线模板 ✗ ⇒ 一旦“就近”那条被硬约束否掉 ✗，
  就没有备选 ✗ ⇒ 要么绕得很远 ✗（长度从 v8 的 347mm 涨到 486mm ✗）、要么退化成违规直连 ✗。
- **约束散落在惩罚项里** ✗ —— 7 个乘子 + 几处硬判废混在一起 ✗ ⇒ 每加一条真约束，
  就换一种方式失败 ✗（overlap / hidden / 绕远 ✓）。
- 长度涨长的主因是**几何约束变严** ✗，不是次序 ✓（v20 无次序 494.7mm ✓ / v21 有次序 486.7mm ✓，基本一样 ✓）。

⇒ 下一步应该**重写“构造”这一层** ✓（保留：合法性检查器 ✓、汇率 K ✓、用户次序 ✓）：

1. 每个网：枚举要连的 bus ✓ → 对每对 bus **枚举所有可用孔对 × 可行折线** ✓；
2. 用 `audit_layout` 的规则**直接筛合法/非法** ✓（不再用惩罚项 ✗）；
3. 在合法候选里按 **长度 + 拥挤 + K×交集** 选 ✓；
4. **没有合法候选就停下并报告**（哪个网 / 哪对孔 / 为什么 ✗），**绝不产出违规几何** ✗；
5. 之后再跑 1-opt / 2-opt / R&R ✓ —— 但只在**合法域内**搜 ✓。

**输入**
- 孔 ↔ bus（126×5 + 4×50 ✓）、元件脚占了哪些孔 ✓、元件本体盖住哪些孔 ✓、元件外形框 ✓
- 每个网需要连哪些"脚所在的 bus" ✓（网表 ✓）

**变量**
- 每个网：用哪些孔当接线点 ✓（一个孔最多一个端点 ✓）
- 每根引线：一条折线路径 ✓（可以 45°/正交 ✓）

**硬约束（必须全部满足，违反 = 判废 ✗）**
1. 一个孔最多一个导线端点 ✓（且不得落在已插脚的孔上 ✓）
2. 引线不得盖住"已接线的孔" > 30% ✓（`obscures()` ✓，正反两个方向都要查 ✓）
3. 引线不得穿过别的元件本体 ✓（自己的元件豁免 ✓）
4. 引线不得重叠（共线段 ✗）✓
5. 一条 bus 上不许挂两个不同网的脚 ✗（会实物短接 ✓）
6. 网必须连通 ✓

**目标（人定的取舍 ✓）**
$$\min\ \underbrace{\text{长度}}_{\text{mm}} + K \times \underbrace{\text{交集}}_{\text{X 交叉 + T 搭线 + 穿元件}}$$
$K = 10$ mm/交集 ✓ —— **人为选定、可调** ✓（`bb_route4.py` 的 `K_MM` ✓）。
**验收必须在文件层做** ✓：`交集 / 长度 / 遮挡 / 重叠 / 孔冲突` 五项全部独立量 ✓。

## 3b. 开始重写后立刻得到的东西（2026-09-26 ✓）

重写第一刀（只动"构造层" ✓）：
- **硬约束不再是惩罚项** ✓：`route_cost` 直接判废（①自交 ②穿别的元件 ③与现有线重叠 ④盖住接线孔
  ⑤新占的孔已被盖 ✓），代价只留 **形状加权长度 ×(1+0.3×拥挤) + K×交集** ✓。
- **删掉所有"退化兜底"** ✗（"重叠直连"✗、"借闲置 bus 绕"✗）⇒ 连不上就**停下并报告** ✓，绝不写违规几何 ✓。
- 候选孔位放宽（12→40、30→60 ✓）+ 失败时报出**每个候选被哪条规则否掉** ✓（`[诊断]` 行 ✓）。

**这一步立刻抓出来的两个东西：**

1. **一个真 bug** ✗：`route_cost` 判"自交"前**忘了先 `simplify()`** ✗ ⇒ 63 个候选里 **37 个被误杀** ✓
   （已修 ✓）—— 与"公式符号写反 ✗"同类：**几何预处理也必须自测** ✓。
2. **一个需要你定方向的设计缺口** ✗：现在停在这里 ✓
   `net BR+: 连不上（2 个不连通块……）`，诊断 `63 个候选 → ③ 重叠×41；② 穿 R1 框×14；② 穿 L1 框×8` ✓
   —— BR+ 的那两个 bus（col17 / col18 上排 ✓）被 **L1 的 20×20mm 板**（上方 y≤57.4 ✓）和
   **R1 的框**（y 67.7∼76.2 ✓）夹住 ✓，中间只剩 row H（y=63 ✓）那条走廊 ✓，**而它已经被先布的 GND 线占了** ✗。
   ⇒ 这正是**次序②③的副作用** ✓："先布电源/地"会让后布的信号线无路可走 ✗。
   ⇒ 两条路可选：**(a)** 先布的电源/地**优先走电源轨与板边** ✓、把中间走廊留给信号线 ✓；
   **(b)** 给先布的线加"留路"约束（在它与后面的线之间留出通道 ✓）。
   （这也是用户第 1 条"主要元件周围应留出走线空间 ✓"的延伸：**留路不只是给元件，也是给后面的线** ✓）

### 3b-2. 规则 a 落地后的事实（2026-09-26 ✓）

- 已按规则 a 实现 ✓：GND/5V（组 0/1）的代价里，给"走中间走廊"的每单位长度加 `MID_PEN`（默认 **3.0** ✓，
  人为可调 ✓）⇒ 电源/地会优先走**电源轨 / 板边** ✓。
- 但实测**没有改变结果** ✗ —— 原因不是代价，是**布局里有一条卡脖子走廊** ✓：
  1. 诊断指名道姓：GND 的那根线走了 `(135,9)→(135,63)→(189,63)` ✓，其中 `(135,63)->(189,63)` 占了 row H ✗；
  2. 44 个 BR+ 候选因此被判"与它重叠" ✗；
  3. 而 BR+ 的 bus（col17/col18 上排 ✓）**只有 row H 这一条合法进口** ✗ ——
     想从电源轨竖直下来（如 `(189,9)→(189,63)` ✓）会**穿过 L1 那块 20×20mm 线圈板** ✗（L1 的板盖住 y≤57.4 ✓）。
  ⇒ **谁先拿到 row H，谁就把另一条网堵死** ✗ —— 这正是"先布电源/地"的代价 ✓，
  光靠代价加权解决不了 ✗ ⇒ 需要 **拆线重排（rip-up & reroute）** ✓：
  某个网连不上时，把它**卡住的那根线**（诊断已给出具体线段 ✓）先抽出来重排 ✓，
  两边都合法才收 ✓ —— 这才是 §4 里"搜索"那一步该做的事 ✓。

### 3b-3. 拆线重排做好了（2026-09-26 ✓）—— 机制有效，剩下的卡在**布局**上

机制（`bb_route4.py` ✓）：连不上 ⇒ 记下"挡路的线段" ⇒ 抽出压在那段上的线（逐次 1→3 根 ✓）
⇒ 先让本网连上 ✓ ⇒ 再把抽出的线重排 ✓ ⇒ **两边都成立**才收 ✓，否则回快照 ✓。

**成功案例** ✓（正是 row H 那个卡脖子 ✓）：
```
[连不上] net BR+：2 个不连通块
[拆线重排] 第 1 次：抽出 1 根挡路的（GND）⇒ 先连 BR+
加线: BR+  sig  pin17H → pin18H  1 段 2.5 mm      ← 最短的那种直连 ✓
加线: GND  sig  pin21H → pin25Z  2 段 25.4 mm     ← GND 让位、改走顶部电源轨 ✓
[拆线重排] ✓ 成功
```
⇒ 说明**次序 + 规则 a + 拆线重排**这个组合是对的 ✓ —— 电源线会让位给信号线 ✓。

**失败案例** ✗ —— `net RC`：
```
[诊断] 2080 个候选 → ② 穿元件 L1 框×1013; ② 穿元件 R1 框×448;
                     ③ 与线段 (198,63)->(342,63) 重叠×278; ② 穿元件 J1 框×171 …
[拆线重排] 第 1/2/3 次没成
```
追因：RC 要连的两条 bus（col22 上排 ↔ col38 上排 ✓）之间，x 198∼261 那一段**只剩一条**
可用横向通道（y=63，夹在 **L1 的板**（y≤57.4 ✓）与 **R1 的框**（y 67.7∼76.2 ✓）之间 ✓）✗，
而它已经被 BR+ / GND 的线占满 ✗。
⇒ 这是**布局**问题 ✗，不是布线问题 ✗ —— 正是用户第 1 条
"**主要元件周围应留出空间走线** ✓"要管的事 ✓：布线器再聪明也变不出空间 ✗。

⇒ 两条路（**等你定** ✓）：
- **(A)** 实现第 1 条：自动布置/微调元件位置 ✓（给每个元件周围按"要走的线数"留通道 ✓）；
- **(B)** 你在 Fritzing 里手工把 L1 / R1 挪一挪 ✓（例如 R1 下移一行 ✓、L1 上移 ✓），
  让那条走廊有 2 条通道 ✓，然后布线器就能收 ✓。
