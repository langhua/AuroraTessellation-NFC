# `min-bringup` —— 像素板最小固件（台架第 ③ 步）

> 目的**只有三个** ✓：证明「**MCU 活着**」「**5 V 在**」「**LED 能亮**」，
> 并且让**不接任何仪器**也能看出「**线圈有没有信号、随距离怎么变**」✓。
> ✗ 不做：链上收发（`bus-protocol.md`）、IAP、基线标定、颜色下发 ✗ —— 那些是后面的事 ✓。

## 1. 它做什么（三件，不多做）

| # | 行为 | 看什么 |
|---|---|---|
| ① | **上电自检**：**红 → 绿 → 蓝** 各 150 ms（再灭 150 ms）；ADC 初始化完再**紫闪一次**。★ 第一帧**故意不用白**（白与「卡住残留的白」肉眼分不开）| **停在哪一色 ⇒ 卡在它后面那一段** ✓；若「红→绿→蓝→又回红」= 芯片在反复复位 ✓ |
| ② | **采 `PD6`（= `A6` = `ADC_IN6`）**：每次 **16 采样累加后 `>>2`** ⇒ **12-bit**（0…4092）| 噪声按 √16 = 4 倍衰减 ✓ |
| ③ | **读数显示在灯上**：**颜色 = 档位**、**亮度 = 档内大小**（≈2 Hz 刷新）| 不用仪器就能判「有没有信号 / 强弱变化」✓ |

**档位**（按 RC 节点电压，`Vref = VDD = 5.00 V`）：

| 读数 | 颜色 | 含义 |
|---|---|---|
| < 120 mV | 蓝 | 几乎没信号 |
| 120 – 400 mV | 青 | 弱 |
| 400 – 1000 mV | 绿 | 中 |
| 1000 – 2000 mV | 橙 | 强 |
| ≥ 2000 mV | 红 | 很强（**可能过压** ⇒ 见 `README` §6 的钳位缺口）|

亮度 = `40 + 215×(mv/2500)` ⇒ 最暗也有 16%（看得见），2500 mV 以上满亮度。
读数 ≈ 0 时灯 **常亮暖白 `(52,40,24)`** ⇒ 判据就一句话：

| 看到 | 结论 |
|---|---|
| **全黑** | 程序没跑起来（或灯这一路坏了）✗ |
| **暖白常亮** | MCU + 灯 + ADC 三样全对，只是还没信号 ✓（★ 改暖白的原因：`(40,40,40)` 盯着看能分出蓝/绿 die，容易与「蓝档」混 ✗）|

✗ 原来那种「每秒 10 ms 的暗白心跳」占空只有 1%，灯只有 1.0×1.0 mm ⇒ 实际看不见，已弃用 ✓。

## 2. 引脚与依据（✗ 不猜，逐条有出处）

| 引脚 | 用途 | 出处 |

| `PD6` | **线圈包络 → ADC** = `A6` = `ADC_IN6` | 同上表 2-1/2-2：`PD6 → A6 / URX` ✓ |

| `PD1` | `SWIO` 烧录 —— **一个字不碰**（配了就别想再烧了 ✗） | 同上，`NETS["SWIO"]` ✓ |

## 2c. ★★ `PD5` 必须真的放电（2026-11-10，用户报「上电白一下、然后常亮红」）

**症状**：上电 `红→绿→蓝→紫` 全部闪过（自检过 ✓）⇒ 暖白**停一下** ⇒ 然后**常亮红** ✗。

**根因**（电路层面 ✓）：`RC` 节点对地只有 `C1`（隔直 ✗）和 `D3`（反偏 ✗）⇒ **没有直流通路**；
`D4`（1N5819）的**反向漏电**给 `C1` 充电 ⇒ 节点**慢慢升到接近 5 V** ✗ ⇒ ADC 读到 ≥ 2 V
⇒ 灯进「红档」✓ —— 而"上电先白一下"正好是 `C1` 还放电着的那几百毫秒 ✓。

**修法**（固件 ✓，设计里本来就留了这根脚 ✓）：`PD5` = **开漏输出低**（不是模拟输入 ✗）
⇒ 每轮：`放电 2 ms → 释放成模拟输入 → 等 3 ms（≈3τ，τ = R1·C1 = 1 ms）→ 采样` ✓
⇒ 读到的才是**包络**，而不是被漏电抬上去的假电平 ✓。

**正确状态**（重烧后应该看到）：`红→绿→蓝→灭→紫` ⇒ **常亮暖白**（`52,40,24`）；
**只有把 NFC 场加到场强够大**时才会变青/绿/橙/红 ✓。

### ★ 后续（同日二次实测）：拔掉 `D4` **仍然漂** ⇒ 改「**相对零点**」✓

把 `D4` 整个拔掉、`R6` 换成 100 kΩ 之后，读数**依然**慢慢漂（0.1–0.5 V）✗
⇒ `D4` 的漏电**不是**（唯一）原因 ✓；再往下换料（如 `BAT54`）也没意义 ✗。
剩下的漂是**节点绝对电平本身**在变（环境电磁/表面漏电/温度），无法用硬件"钉死"。

⇒ 固件改成 **零点标定 ＋ 门限**（任何慢漂都吃不消这一招 ✓）：

| 步 | 做什么 |
|---|---|
| 上电 | 紫闪后**连采 16 次取平均**作为零点 `base_code`（此刻应无场 ✓）；**标定期间灯做一次紫色呼吸**（亮 → 全暗 → 亮，约 2 s）⇒ 一眼看出"在标定"，不是"卡住" ✓ |
| 循环 | 只算 `code − base_code`；差值 < **`NOISE_MV`（500 mV）** ⇒ 当作无信号 ⇒ **暖白** ✓ |
| 含义 | 颜色反映的是**高出零点的量** ✓ ⇒ 漂移不再翻色，但**换场/重上电**要重新标定 ✓ |

### ★ 第三次修（同日实测：`D4` 拔掉后节点 0.62–0.73 V，30 s 只动 110 mV，但**灯还在变**）

**根因不在电路** ✓：节点已经很稳了 ✗；变的是**读数就在门限附近抖** ——
原来门限 120 mV，而 120–400 mV 这一段对应**暗青色**（`(0,200,255)` × 亮度 ≈ (0,39,50)）
⇒ 跟暖白 `(52,40,24)` 一对比，颜色差得很明显 ✗。

⇒ 两条一起改 ✓：

| 项 | 改法 |
|---|---|
| 门限 | `NOISE_MV` **120 → 500 mV**（真正的 NFC 信号是伏级 ✓）|
| 防抖 | **滞回 ＋ 连续 2 次确认**：`≥500` 要连中 2 次才进档、`<350`（`RELEASE_MV`）要连中 2 次才退回 ✓ ⇒ 单次跳动与慢漂一律不翻色 ✓ |
| 档位 | `800 / 1500 / 2500 / 3500 mV`（原来 120/400/1000/2000 ✓ 同步上移）|

⚠ 代价：从"有场"到"开始报档位"会慢 **≈1 s**（两次 500 ms 采样）✓ 当指示用够了 ✓。


⚠ 前提：**上电那一刻没有场**。有场时上电 = 把那个场当零点（台架上可接受 ✓）。

## 2d. 驱动为什么从 SPI 换成了 GPIO 位翻转（2026-11-07）
本板上 SPI1 这条路走不通：`PC6` 复用成 `MOSI` 后**空闲一直停在 ~4.9 V**（WS2812 把持续高电平
读成一串 1 ⇒ 全灯白），探针读回 `SPI1_CTLR1` 也不对；而**同一根脚当普通输出完全正常**
（1 Hz 方波，万用表 0↔5 V 实测）。常量已逐条与 SDK 头文件对齐（`SPI1_BASE = 0x40013000`、
`RCC_SPI1EN = 0x1000`、`CTLR1` 位值、`APB2PCENR` 偏移 `0x18`、结构体成员顺序），
配置层面查不出错，手边又没有示波器 —— 继续猜只会拖时间。

⇒ 改用**已经实测可用**的 GPIO 位翻转：`src/ws2812_gpio.c`
（SPI 版原样留在 `src/ws2812_spi.c`，**不参与编译**；要切回来只改 `Makefile` 的 `SRCS` 一行）

| | GPIO 位翻转（现在） | SPI1 + MOSI（原方案） |
|---|---|---|
| 依赖 | 只用普通推挽输出的 GPIO ✓ | SPI1 外设（本板不响应 ✗） |
| 代价 | 一帧 24 位占 CPU ≈ 32 µs | 后台移位 / 可上 DMA |
| 本固件是否可接受 | ✓ 0.5 s 才发一帧 | — |

**位时序（★ 按逻辑分析仪实测标定，不是按理论周期算）**

实测反推出的模型（2026-11-07，24 MHz 采样逐样点统计）：

| 常数 | 值 | 怎么来的 |
|---|---|---|
| 1 个 `nop` | ≈ **3 个采样点 ≈ 0.125 µs** | `'0'` 用 3 nop 实测 15 点、`'1'` 用 6 nop 实测 24 点 ⇒ 差 9 点 / 3 nop |
| 两次 `store` 之间固定开销 | ≈ **6 点 ≈ 0.25 µs** | 15 − 3×3 = 6 |
| ⇒ 高电平 | **= 6 + 3 × nop 个点** | 上两行合并 |

当前取值与规格对照：

| 位 | nop 数 | 高电平 | 规格 |
|---|---|---|---|
| `'0'` | 1 | 9 点 ≈ **0.375 µs** | 0.25–0.55 ✓ |
| `'1'` | 4 | 18 点 ≈ **0.75 µs** | 0.65–0.95 ✓ |
| 位周期 | — | ≈ **1.65 µs** | ≤1.85 ✓ |

★ 两条踩过的教训（都靠实测才发现的）：

1. **`bnez` 必须放在两次 `store` 之前**：一次跳转约等于 4 条指令（≈0.55 µs），
   落在"高→低"之间会让 `'0'`/`'1'` 变得一样宽，芯片分不出来 ✗
2. **RV32EC 只有 x0–x15**：`t3`（x28）不存在，汇编里临时寄存器要用 `a1` ✗

## 3. 数字从哪来（全部可复查）
| 数值 | 依据 |
|---|---|
| 时钟 **24 MHz**、**不配 PLL** | 复位默认值；EVT `system_ch32v00x.c` 的缺省分支就写着 `SystemCoreClock = HSI_VALUE`（24 MHz）⇒ 这是 WCH 认可的配置 ✓ |
| `SPI1` = `PCLK2/4` = **6 MHz** | `SPI_BaudRatePrescaler_4 = 0x0008`（`ch32v00x_spi.h:84`）✓ |
| WS2812 位 = **8 个 SPI 位**（1.333 µs） | 6 MHz ⇒ 1 位 0.1667 µs ✓；`'0' = 11000000`（高 0.33 µs）、`'1' = 11111000`（高 0.83 µs）—— 都在 WS2812B 的容差内（T0H 0.4±0.15、T1H 0.85±0.15、周期 1.25±0.6 µs）✓ |
| 锁存 = **1 ms 低电平** | 复位码要求 > 280 µs ✓（留足余量）|
| ADC 时钟 = `PCLK2/2` = **12 MHz** | `CFGR0` 的 `ADCPRE` 复位值 = ÷2 ✓ ⇒ 正好落在数据手册 ADC 特性表的标定点（`fADC = 12 MHz` 那一列）✓ |
| 采样时间 = **241 周期**（≈20 µs） | `ADC_SampleTime_241Cycles = 0x07`（`ch32v00x_adc.h`）✓ —— `R1 = 10 kΩ` 源阻抗偏高，采样窗给足 ✓ |
| `EOC` = `STATR` bit1、`SWSTART` = `CTLR2` bit22、`CAL/RSTCAL` = bit2/bit3 | `ch32v00x_adc.c` 里的宏值 ✓ |
| `TXE` = `STATR` bit1、`SSM` = bit9、`SSI` = bit8、`SPE` = bit6 | `ch32v00x_spi.h` 的 `SPI_I2S_FLAG_*` / `SPI_NSS*` ✓ |
| 锁存 = **固定延时 1 ms**（✗ **不看 `BSY`**） | 24 位 × 1.33 µs ≈ 32 µs ✓ ⇒ 1 ms 有 30 倍余量。`BSY` = `STATR` bit7 虽然存在，但**死等它会整片卡住**（2026-11-07 实测 ✓）|

> ★ **锁存不要写 `while (SPI1_STATR & SPI_STATR_BSY)`**（2026-11-07 实测踩到 ✗）：
> 症状是**灯停在自检第一帧的满亮度白、再也不动** —— 看起来和「MCU 根本没跑」一模一样 ✗，
> 实际是 24 位已经发出去了、程序死在等那个状态位。`TXE` 只保证发送缓冲空，
> 最后一位还要 ≤1.33 µs 才移出去，用固定延时覆盖就够 ✓。
> ⇒ **凡是「死等某个外设状态位」的地方，都要先问一句：它不清零我会不会永远卡在这。**
> 现在 `TXE` / `EOC` / `RSTCAL` / `CAL` 四处等待**都带上了循环上限** ✓（超时就继续往下走）。
| Flash 起点 **0x00000000**、16 K；RAM **0x20000000**、2 K | EVT `Ld/Link.ld` ✓（CH32V003 的代码区就在 0，**不是** 0x08000000 ✗）|

## 5. 怎么烧

接线见项目 README **§六十六**（三根：`DIO` / `5V0` / `GND`）✓；要点只有两条：

1. **芯片先上电**再点连接；`WCH-LinkE` 拨到 **RISC-V**；
2. ✗ **不要同时接两个 5 V 源** ✗（LinkE 的 `5V0` 与 J1/J2 那条 5 V 只选一个）。

烧完应当看到：**红 → 绿 → 蓝 各闪一下 → 灭 → 紫闪一下 → 紫色呼吸一次（≈2 s）→ 常亮暖白**；
拿 NFC（手机处于找卡状态）靠近线圈就逐档变蓝/青/绿/橙/红（**进档门限 500 mV** ✓）。
