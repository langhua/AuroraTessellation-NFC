# `min-bringup` —— 像素板最小固件（台架第 ③ 步）

> 目的**只有三个** ✓：证明「**MCU 活着**」「**5 V 在**」「**LED 能亮**」，
> 并且让**不接任何仪器**也能看出「**线圈有没有信号、随距离怎么变**」✓。
> ✗ 不做：链上收发（`bus-protocol.md`）、IAP、基线标定、颜色下发 ✗ —— 那些是后面的事 ✓。

## 1. 它做什么（三件，不多做）

| # | 行为 | 看什么 |
|---|---|---|
| ① | **上电自检**：板载 `WS2812B-1010`（`LED2`）**满亮度**白光闪 **3 次**（200/255，各 200 ms 亮 / 200 ms 灭）—— ★ **排在 ADC 初始化之前**（自检不许被别的模块卡住）| 闪了 ⇒ MCU 起来了、SPI 时序对、这颗灯能点亮 ✓ |
| ② | **采 `PD6`（= `A6` = `ADC_IN6`）**：每次 **16 采样累加后 `>>2`** ⇒ **12-bit**（0…4092）| 噪声按 √16 = 4 倍衰减 ✓ |
| ③ | **读数显示在灯上**：**颜色 = 档位**、**亮度 = 档内大小**（≈2 Hz 刷新）| 不用仪器就能判「有没有信号 / 强弱变化」✓ |

**档位**（按 RC 节点电压，`Vref = VDD = 5.00 V`）：

| 读数 | 颜色 | 含义 |
|---|---|---|
| < 120 mV | 蓝 | 几乎没信号 |
| 120 – 400 mV | 青 | 弱 |
| 400 – 1000 mV | 绿 | 中 |
| 1000 – 2000 mV | 橙 | 强 |
| ≥ 2000 mV | 红 | 很强（**可能过压** ⇒ 见 `README` §6 的钳位缺口）|

亮度 = `40 + 215×(mv/2500)` ⇒ 最暗也有 16%（看得见），2500 mV 以上满亮度。
读数 ≈ 0 时灯 **常亮暗白（40/255）** ⇒ 判据就一句话：

| 看到 | 结论 |
|---|---|
| **全黑** | 程序没跑起来（或灯这一路坏了）✗ |
| **暗白常亮** | MCU + SPI + 灯三样全对，只是还没信号 ✓ |

✗ 原来那种「每秒 10 ms 的暗白心跳」占空只有 1%，灯只有 1.0×1.0 mm ⇒ 实际看不见，已弃用 ✓。

## 2. 引脚与依据（✗ 不猜，逐条有出处）

| 引脚 | 用途 | 出处 |
|---|---|---|
| `PC6` | **LED 数据** = `SPI1_MOSI`（默认复用） | 数据手册 `CH32V003DS0.PDF` V1.8 表 2-2：`PC6 → MOSI` ✓ |
| `PD6` | **线圈包络 → ADC** = `A6` = `ADC_IN6` | 同上表 2-1/2-2：`PD6 → A6 / URX` ✓ |
| `PD5` | 与 `PD6` **同一节点**（`RC` 网）⇒ 设成**模拟输入**（高阻，不注入电流） | `hardware/pixel/pixel_nets.py` 的 `NETS["RC"]` ✓ |
| `PD1` | `SWIO` 烧录 —— **一个字不碰**（配了就别想再烧了 ✗） | 同上，`NETS["SWIO"]` ✓ |

## 3. 数字从哪来（全部可复查）

| 数值 | 依据 |
|---|---|
| 时钟 **24 MHz**、**不配 PLL** | 复位默认值；EVT `system_ch32v00x.c` 的缺省分支就写着 `SystemCoreClock = HSI_VALUE`（24 MHz）⇒ 这是 WCH 认可的配置 ✓ |
| `SPI1` = `PCLK2/4` = **6 MHz** | `SPI_BaudRatePrescaler_4 = 0x0008`（`ch32v00x_spi.h:84`）✓ |
| WS2812 位 = **8 个 SPI 位**（1.333 µs） | 6 MHz ⇒ 1 位 0.1667 µs ✓；`'0' = 11000000`（高 0.33 µs）、`'1' = 11111000`（高 0.83 µs）—— 都在 WS2812B 的容差内（T0H 0.4±0.15、T1H 0.85±0.15、周期 1.25±0.6 µs）✓ |
| 锁存 = **1 ms 低电平** | 复位码要求 > 280 µs ✓（留足余量）|
| ADC 时钟 = `PCLK2/2` = **12 MHz** | `CFGR0` 的 `ADCPRE` 复位值 = ÷2 ✓ ⇒ 正好落在数据手册 ADC 特性表的标定点（`fADC = 12 MHz` 那一列）✓ |
| 采样时间 = **241 周期**（≈20 µs） | `ADC_SampleTime_241Cycles = 0x07`（`ch32v00x_adc.h`）✓ —— `R1 = 10 kΩ` 源阻抗偏高，采样窗给足 ✓ |
| `EOC` = `STATR` bit1、`SWSTART` = `CTLR2` bit22、`CAL/RSTCAL` = bit2/bit3 | `ch32v00x_adc.c` 里的宏值 ✓ |
| `TXE` = `STATR` bit1、`SSM` = bit9、`SSI` = bit8、`SPE` = bit6 | `ch32v00x_spi.h` 的 `SPI_I2S_FLAG_*` / `SPI_NSS*` ✓ |
| 锁存 = **固定延时 1 ms**（✗ **不看 `BSY`**） | 24 位 × 1.33 µs ≈ 32 µs ✓ ⇒ 1 ms 有 30 倍余量。`BSY` = `STATR` bit7 虽然存在，但**死等它会整片卡住**（2026-11-07 实测 ✓）|

> ★ **锁存不要写 `while (SPI1_STATR & SPI_STATR_BSY)`**（2026-11-07 实测踩到 ✗）：
> 症状是**灯停在自检第一帧的满亮度白、再也不动** —— 看起来和「MCU 根本没跑」一模一样 ✗，
> 实际是 24 位已经发出去了、程序死在等那个状态位。`TXE` 只保证发送缓冲空，
> 最后一位还要 ≤1.33 µs 才移出去，用固定延时覆盖就够 ✓。
> ⇒ **凡是「死等某个外设状态位」的地方，都要先问一句：它不清零我会不会永远卡在这。**
| Flash 起点 **0x00000000**、16 K；RAM **0x20000000**、2 K | EVT `Ld/Link.ld` ✓（CH32V003 的代码区就在 0，**不是** 0x08000000 ✗）|

## 4. 怎么编

```bat
build.bat            ← 推荐：自动找 MounRiver Studio 2 自带的 RISC-V gcc
make                 ← 工具链已在 PATH 时
make clean
```

产物（`build/`，**不入库** ✓）：

| 文件 | 用途 |
|---|---|
| `min-bringup.hex` | **WCH-LinkUtility 直接烧这个** ✓ |
| `min-bringup.bin` / `.elf` / `.map` | 备份 / 看符号 |

常量都在 `Makefile` 里，通常不用改：`TC_DIR`（工具链）、`PREFIX`（GCC12 = `riscv-wch-elf-`、
GCC15 = `riscv32-wch-elf-`）。`-march=rv32ec -mabi=ilp32e` 是 CH32V003 那颗核的唯一正确组合 ✓。

> ✗ 本工程**不依赖 WCH SDK / 不依赖任何仓库外文件** ✓ —— `regs.h` 只写用到的寄存器、
> `startup.S` 与 `ch32v003.ld` 都是自己写的 ✓（照 EVT 的**行为**写，不拷代码 ✓）。

## 5. 怎么烧

接线见项目 README **§六十六**（三根：`DIO` / `5V0` / `GND`）✓；要点只有两条：

1. **芯片先上电**再点连接；`WCH-LinkE` 拨到 **RISC-V**；
2. ✗ **不要同时接两个 5 V 源** ✗（LinkE 的 `5V0` 与 J1/J2 那条 5 V 只选一个）。

烧完应当看到：**满亮度白光闪 3 次** ⇒ 之后灯**常亮暗白**（没信号时）；拿磁铁靠近线圈就逐档变蓝/青/续/橙/红。

## 6. 怎么验证「编译出来的东西是对的」

编译本身只证明语法过 ✓；下面三条是**看产物**的检查（`objdump` / `readelf` 在同一个工具链目录里）：

| 检查 | 期望 |
|---|---|
| 入口 | `0x00000000: j reset` —— **不是** `j 0` 也不是空 ⚠️ |
| 向量表 | `0x04` 是 0、`0x08` 起全是 `trap`（本固件不开中断 ⇒ 出异常就停在 `trap`，LED 保持最后一次颜色 ⇒ 一眼看出"死了"）|
| 栈 | `reset` 里 `la sp, _e_stack` ⇒ **0x20000800**（= RAM 末尾）|

实测（2026-11-06 ✓，`text = 1176 B / data 0 / bss 0`）：

## 7. 已知限制（下一手）

| # | 限制 | 为什么现在不做 |
|---|---|---|
| 1 | **没有数字读数出口** | 这块板**没有把 UART 引到可探的地方** ✗：`PD5`(=UTX) 与 `PD6` 同在 `RC` 节点 ✓、`PD2`(=DATA_OUT) 没有 USART 复用 ✓（数据手册表 2-2）⇒ 现在只能"灯看" ✓。绝对数值用万用表量 `pin16I`（RC 节点）✓ |
| 2 | 只用 `Vref = VDD` ⇒ **5 V 轨的噪声就是测量噪声** | 已靠"采样避开 LED 刷新"缓解 ✓；要更准就读内部基准（`ADC_Channel_Vrefint` = ch8）✗ 未做 |
| 3 | 没做**基线/零点** | `PD5` 已接在 `RC` 节点上 ✓ ⇒ 以后固件可以把它当开漏"放电"采零基线（`data-acquisition.md` §4 c ✓），本轮只把它设成高阻模拟输入 ✓ |
| 4 | 无看门狗、无链上协议 | 台架最小件，故意 ✗ |
