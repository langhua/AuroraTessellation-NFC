## 1. 它是什么（术语）

借鉴 WS2812 的**两条**核心思想 —— 不是它的线码：

| 层面 | 术语 | 我们的做法 |
|---|---|---|
| 拓扑 | **单向菊花链**（unidirectional daisy chain） | 每块两个口，链式串下去 ✓ |
| 线码 | 单线、脉宽编码、自定时 | ← **不照抄** ✗：我们加**主控发的节拍当软时钟**（时序更稳 ✓） |
| 寻址 | **隐式寻址 / 位置寻址**（implicit addressing） | 位置 = 链上先后 ✓ **不用地址字段** ✓ |
| 行为 | **分布式移位寄存器**（distributed shift register） | 每级"取走自己那份、转发剩余" ✓ |

**和 I2C 的关系**：开漏 + 上拉 + 主从轮询这一段**很像 I2C** ✓，但有两处不同 ✗：
① **少了 `SCL` 时钟线** ✗；② **拓扑是链、不是共线总线** ✗（见 §2 ✓）。
⇒ 不能直接用 I2C 外设 ✗；位定时靠**主控发节拍 + 节点自己测时**（或单线 UART —— CH32 是否支持
"单线半双工"模式**需查手册确认** ✗）。

> ⚠️ 芯片里**没有出厂"位置"信息** ✗（就算有唯一 ID 也只是身份、跟物理顺序无关 ✗）⇒ 位置**必须靠枚举**得到。

## 2. 物理层（已定）

- 三根线：`5V` / `GND` / `DATA`；**GND 居中**（万一错插先撞 GND，不把 5V 灌进数据脚 ✓）
- **★ 拓扑：与 WS2812 完全一致的单向接力链**（2026-09-26 用户定 ✓）：数据**只往下游走** ✓，
  每块收到后**再生转发** ✓；**位置 = 物理顺序** ✓，**帧里不带地址** ✓；断一块 ⇒ 下游全灭 ✗（同 WS2812 ✓）。
- **每块用两个脚**（不是同一个脚 ✗）：**上游脚**（收）+ **下游脚**（发）✓—— 14 个备用脚够用 ✓；
  固件自动识别“哪口在收” ⇒ **插哪个口都行** ✓（口 A / 口 B 同型 ✓）
- `DATA`：**开漏 + 上拉 4.7~10 kΩ**，**两端都能驱动** ✓，非说话方一律**高阻** ✓
  （**驱动** = 引脚设成输出 ✓；**不驱动** = **高阻输入**、只听 ✓ —— 上电后、复位后、没轮到时都保持高阻 ✓）
- 每块板两个口的 `DATA` 接到 MCU 的**同一个脚** ✓（否则读数回不来 ✗，见 `connector-plan.md` §0）
- `5V` / `GND` 穿链累积 ✗ ⇒ 电流预算按**全部同时点亮**核；每口 `5V` 串 **PPTC / 保险** ✓
- 每个口的 `DATA` 串 **100 Ω**（阻尼 + 限流，防"两个节点同时驱动"时烧脚 ✓）
```mermaid
flowchart LR
  H["主控"] ==>|"3 线"| N1["第 1 块<br/>index 0"]
  N1 ==>|"3 线"| N2["第 2 块<br/>index 1"]
  N2 ==>|"3 线"| N3["第 3 块<br/>index 2"]
  N3 -.->|"再往后…"| N4["第 n 块"]
  A["每块板：口 A → 上游脚（收）、口 B → 下游脚（发）<br/>固件自动识别哪边在收 ⇒ 插哪个口都行"]
  B["数据只往下游走、每块再生转发<br/>⇒ 断一块、下游全灭"]
  N2 --- A
  N4 -.-> B
```
## 3. 位定时（草案 · 待评审）

- 主控发**节拍**（高低电平脉冲），节点用定时器在每个节拍的固定相位采样 ✓
- 位编码建议**简单归零码**：一个位周期 T，前半高 = `1`、后半高 = `0`（或主控统一给时钟、节点在固定点回读 ✓）
- ★ **方向：直接照 WS2812 的编码**（2026-09-26 定 ✓ —— 既然拓扑与它一致 ✓）：位周期 **1.25 µs（800 kHz）** ✓、
  `T0H`/`T1H` 按 WS2812 比例 ✓、**长低电平（>50 µs）= 复位** ✓ ⇒ 现成的 WS2812 时序经验可直接复用 ✓
  ⚠️ 但差别要实测 ✗：WS2812 是**硬件**逐位再生 ✓；我们是 MCU ⇒ **逐位再生太紧** ✗ ⇒ 先按
  **逐字节 / 逐帧** 接力做 ✓，实测时序余量后再定（这一项留到固件阶段验证 ✗）
- ⏳ 待定：位周期 T（如 2 µs ⇒ 500 kbit/s ✓）、采样相位、各节点 RC 偏差容限（± % ✗ 要实测）
- 备选：若 USART 单线半双工可用 ⇒ 直接用它 ✓（协议栈最省事 ✓，帧格式照 §4）

## 4. 帧格式（草案 · 待评审）

### 4.1 下行帧（主控 → 下游，逐级转发）

| 字段 | 长度 | 说明 |
|---|---|---|
| 同步头 | 2 B | 节点复位/对齐用（如 `0xAA 0x55` ✓） |
| 命令 | 1 B | `0x01` 枚举 / `0x02` 颜色 / `0x03` 回读请求 |
| 参数 | 1~2 B | 依命令（如 `count` = 链上节点数 ✓） |
| 载荷 | N B | 颜色帧：每节点 3 B（RGB）；枚举帧：1 B 计数 |
| CRC | 1 B | 校验（可选，先跑通再上 ✓） |

### 4.2 位置枚举（上电走一遍，之后位置即地址）

```mermaid
sequenceDiagram
    participant H as 主控
    participant P1 as 第 1 块（未登记）
    participant P2 as 第 2 块（未登记）
    H->>P1: 枚举帧 N=0
    Note over P1: 还没登记 ⇒ 认领它<br/>my_index = 0，写 Flash
    P1->>P2: 我重新发一帧 N=1
    Note over P2: 认领 ⇒ my_index = 1
    P2->>P2: 继续往下发 N=2 …
```

- 每块把收到的 `N` 记成**自己的位置** ✓，再往下游发 `N+1` ✓
- 一路走完，**每块自知第几块** ✓✓；主控**不需要回执** ✓（想知道总长就用"查询"✓）
- 位置存 Flash ✓；若帧里的 `count`/`version` 与记录不符 ⇒ 重新枚举 ✓
- **枚举由主控发起、节点永远被动** ✓（节点不会自己去“找阵列” ✗）⇒ 触发时机：
  **① 上电**走一遍 ✓；**② 之后任何时候**主控发现 `count`/`version` 对不上
  （加了板 ✓、拔了板 ✓、某块重启过 ✓）就**重发一次枚举帧** ✓ —— 不用人工干预 ✓
- **单机 ↔ 链 可热切换** ✓：收不到合法帧 ⇒ 单机模式自己显示 ✓；**一旦收到合法帧就参与** ✓
  （**不用重启** ✓）—— 这正是“没轮到自己就高阻”带来的好处 ✓：可以随时插到一条
  **正在工作**的链上 ✓，或从链上拔下来 ✓

### 4.3 颜色帧（运行时，完全照 WS2812 的思路）

- 帧 = `[同步头][0x02][count][RGB × count][CRC]`
- 每块：**取走前 3 字节**当自己的颜色 ✓，**把剩余原样转给下游** ✓
- ⇒ **不用地址** ✓ 位置即地址 ✓；断一块 ⇒ 下游全灭 ✗（和 WS2812 一样 ✓，靠 `count` 判断断点 ✓）

```mermaid
sequenceDiagram
    participant H as 主控
    participant P1 as 第 1 块
    participant P2 as 第 2 块
    H->>P1: [同步头][0x02][count][RGB×count][CRC]
    Note over P1: 取走前 3 B（自己的颜色）<br/>更新板载 1010
    P1->>P2: 剩余原样转发
    Note over P2: 取走下一个 3 B<br/>继续往下发
```

### 4.4 回读（半双工的反向时隙）

- 主控广播 `[同步头][0x03][n]` ⇒ **位置 = n** 的那块，在随后的 k 个时隙里**开漏拉低下游线**发它的读数位 ✓
- **中间节点做“低脉冲接力”** ✓——这是**唯一一处必要地超出 WS2812** 的地方 ✗
  （WS2812 本身**没有回读** ✗，可我们必须把每个像素的场强收回来 ✓）：
  在**下游侧**看到低电平 ⇒ **立刻把自己的上游侧也拉低** ✓；节点**只“传”不“造”** ✗
  （不主动注入新脉冲 ✓）⇒ 不会撞总线 ✓
- 其余节点（非本次接力路径）一律**高阻** ✓
- 传播延迟 = 逐级叠加（µs 级 ✓）⇒ 时隙预算不变 ✓（下面那行数字仍成立 ✓）
- 10~12 bit ADC ⇒ 每轮 64 块 ≈ 640~768 个时隙 ✓ —— 慢，但场强成像不需要高帧率 ✓

```mermaid
sequenceDiagram
    participant H as 主控
    participant P1 as 第 1 块（index 0）
    participant P2 as 第 2 块（index 1）
    participant P3 as 第 3 块（index 2）
    H->>P1: [同步头][0x03][n=2]
    P1->>P2: 原样转发
    P2->>P3: 原样转发
    Note over P3: index 匹配 ⇒ 在自己的时隙<br/>把下游侧拉低（发这一位）
    P3-->>P2: 下游侧看到低电平
    Note over P2: 低脉冲接力：<br/>立刻把上游侧也拉低
    P2-->>P1: 低电平传上来
    P1-->>H: 同一脉冲到达主控
    Note over H: 主控直接读这根线 ⇒ 得到这一位
```

## 5. 节点状态机

```mermaid
stateDiagram-v2
    [*] --> 直通
    直通 --> 登记: 收到枚举帧
    登记 --> 直通: 发 N+1 给下游
    直通 --> 取色: 收到颜色帧
    取色 --> 直通: 取走 3 B / 转发剩余 / 更新 LED
    直通 --> 回读: 收到回读请求 且 index 匹配
    回读 --> 直通: 按时隙驱动完
```

铁律：**任何时刻只有"被授权"的节点驱动** ✓；其余全部**高阻**（一个电平都不推 ✗）。

**"驱动"到底指什么**：**驱动** = 引脚设成输出（推挽拉高/拉低 ✓，回读时**开漏拉低** ✓）；
**不驱动** = 引脚设成**高阻输入**、只听 ✓。轮到你时**必须**驱动，共两处：
① **转发**（直通时把帧再发下游 ✓）；② **回读**（`index` 匹配时按自己的时隙开漏拉低 ✓）。

**为什么不许抢驱动**：`DATA` 是**收发共用的线** ✓ —— 两个节点同时驱动（一个推高、一个拉低）
就是**短路** ✗，可能烧引脚 ✗ ⇒ 每节点串 100 Ω 只是"万一"的阻尼 ✓，铁律本身才是保险 ✓。
**两种模式共存（一张图看切换）**：

```mermaid
stateDiagram-v2
    [*] --> 单机
    单机 --> 链中继: 收到合法帧（如枚举帧）
    链中继: 直通 / 取色 / 回读接力
    链中继 --> 单机: 长时间收不到帧（主控关机 / 拔链）
```
## 6. 失败模式与对策

| 现象 | 原因 | 对策 |
|---|---|---|
| 下游全灭 | 某块断电/损坏 | 帧里带 `count`，主控能定位断点 ✓；**5V/GND 是穿链并接**的 ⇒ 电源不会断 ✓（但 **`DATA` 是接力链** ✗ ⇒ 坏一块、下游仍全灭 ✗）|
| 总线锁死 | 两个节点同时驱动 ✗ | 只授权时隙驱动 ✓ + 每节点串 100 Ω ✓ |
| 位置错乱 | 上电顺序/丢帧 | 帧头 + `count/version` 校验 ⇒ 不符就重新枚举 ✓ |
| 反压/错插 | 插错口 | 两口**完全等价** ✓（怎么插都对 ✓）；每口 5V 串 PPTC ✓；GND 居中 ✓ |

断链时的现场是这样的（坏一块，下游全部转入单机模式，不会互相干扰 ✓）：

```mermaid
flowchart LR
  H["主控"] --> B1["第 1 块"] --> B2["第 2 块"] --> X["✗ 某块坏了"]
  X -.->|"下游收不到帧"| LOST["第 3 块及以后：转入单机模式<br/>自己显示、不报错"]
  N["主控拿帧里的 count 与实际应答对比<br/>⇒ 能定位断点"]
  X -.- N
```

## 9. 固件更新：链上 IAP ＋ `SWIO`「保命通道」（草案 · 2026-10-16）

★ **一句话**：日常与现场升级**走链** ✓（不用再碰测试点 ✓）；但 `SWIO` 的测试点 **不能取消** ✗
—— 它负责几个「链进不去」的时刻 ✓。

### 9.1 链进不去的四个时刻

| 时刻 | 为什么链不行 | 用什么 |
|---|---|---|
| **① 空白芯片第一次**（贴片前 / 新板）| Flash 里什么都没有 ⇒ 没有代码能「接住」链上的帧 ✗ | `SWIO` ✓（或用治具**贴片前离线烧** ✓）|
| **② 链断 / 中间某块坏** | §2：数据**只往下游走、每块再生转发** ✓ ⇒ 断点**下游全灭** ✗（同 WS2812 ✓）⇒ 卡在断点后面的板子收不到任何东西 ✗ | 逐块 `SWIO` ✓ |
| **③ 固件刷坏 / 起不来** | 应用不再运行 ⇒ 它**不会再接收**更新 ✗ | `SWIO` ✓ |
| **④ 调试**（单步 / 断点 / 看寄存器）| IAP 给不了调试 ✗ | `SWIO` ✓ |

⇒ **口径**：`TP1`（`SWIO` 测试点，库件 = `NetLabel-Pad` ✓）的定位就是**保命通道** ✓ ——
留着 ✓（成本 = 一颗 2.0 mm 盘 / 1.0 mm 孔的 THT 圆焊盘 ✓，可夹探针、可插 2.54 排针 ✓）。
它接的是 `PD1` ✓（CH32V003 **只有 SDI 这一个下载口** ✓）、**平时悬空** ✓
（出处：[`pixel-netlist.md`](pixel-netlist.md) §2/§3 ✓、[`README.md`](README.md) 4.3 ✓、`pixel_nets.py` 的 `SWIO` 注 ✓、`_work/_bb/u1.fzp` 的脚描述 ✓）。

### 9.2 帧：加一组 `IAP_*` 命令（沿用 §4.1 的格式 ✓）

| 命令 | 名称 | 方向 | 载荷 |
|---|---|---|---|
| `0x10` | `IAP_BEGIN` | 下行 | 镜像长度 / 版本 / 整幅 CRC |
| `0x11` | `IAP_DATA` | 下行 | 页序号 + 该页数据 |
| `0x12` | `IAP_END` | 下行 | 整幅 CRC（各块自查 ✓）|
| `0x13` | `IAP_STATUS` | **上行** | 进度 / 错误码（走 §4.4 的**反向时隙接力** ✓）|

- 帧结构、同步头、CRC 全照 §4.1 ✓；**只有这一组命令**的行为和 §4.3（颜色帧）不同 —— 见 9.3 ✓；
- **只能由主控发起** ✓（节点永远被动 ✓ §4.2 ✓）；建议进 IAP 前先按 §3 发**长低电平复位** ✓、
  并带 `version` 校验 ✓（照 §4.2 的 `count`/`version` 思路 ✓）；
- 失败定位：谁没跟上，用 §6 的 `count` 比对法定位 ✓；`IAP_STATUS` 走回读时隙 ✓
  ⇒ 主控能知道「打到第几块、哪块失败」 ✓。

### 9.3 两种形态：广播式 / 逐块式

**(a) 广播式（推荐 ✓）** —— 每块收到的**是同一幅镜像** ✓（✗ 不是各取一份 ✗）：每块
**边转发边自己写 Flash** ✓ ⇒ 头一块把整幅镜像广播一遍，**所有块同时写完** ✓，线上只过一遍 ✓
⇒ 整串的在线时间 ≈ 传一遍的时间 ✓：

```
16 KB × 8 ÷ 800 kbps ≈ 0.16 s ✓（＋ 帧头 / 逐级转发延迟 ⇒ 秒级 ✓）
```

⚠️ 「边转发边写」要内存与时序规划 ✗：`RAM 2 KB` ✓（[`README.md`](README.md) §4 ✓）装不下 16 KB ✗
⇒ 必须**分页**（收一页、写一页 ✓）；页大小 / 「写非当前页」/ 写之前要不要关中断或从 RAM 跑
写例程 —— **一律照手册** ✓（见 9.5 ✓）。

**(b) 逐块式** —— 帧里带目标 `index` ✓（§4.2「位置即地址」✓），只让那一块写 ✓；
✗ 慢 N 倍 ✗ ⇒ 只在「只修一块」时用 ✓。

```mermaid
sequenceDiagram
    participant H as 主控
    participant P1 as 第 1 块（index 0）
    participant P2 as 第 2 块（index 1）
    H->>P1: [同步头][0x10][长度/版本][CRC]
    P1->>P2: 原样转发（同时自己开始收页）
    Note over P1: 收一页 ⇒ 写一页<br/>（写应用区，不碰 bootloader 页）
    P1->>P2: [同步头][0x11][页 n][数据][CRC]
    Note over P2: 同样：转发 ＋ 自己写
    P1->>P2: [同步头][0x12][整幅 CRC]
    Note over P1: 整幅 CRC 对 ⇒ 置「有效」标志
    Note over P2: 各自校验、各自置标志
```

### 9.4 分区与「变砖」防护

- `Flash` 分两区：**bootloader 区**（**永不自我擦除** ✗）＋ **应用区** ✓；页边界按手册的
  **擦除粒度**定 ✓（✗ 本文不写未核实的数字 ✗）；
- **铁律**：更新过程**不许擦到 bootloader 自己那一页** ✗ —— 擦了 ⇒ 链再也进不去 ⇒ 只剩 `SWIO` 救 ✓；
- 掉电防护：**整幅 CRC 通过之后**才写「有效标志」 ✓（思路同 §4.2 的 `count`/`version` ✓）
  ⇒ 半截镜像不会被当成有效 ✓；起不来时 bootloader 停在等待状态 ✓ 等主控重发 ✓；
- 建议 bootloader **只看链、不依赖应用** ✓（应用坏了也不影响它接帧 ✓）。

### 9.5 要照手册确认的（我不替你拍 ✗）
